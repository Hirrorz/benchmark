常驻设置 ep8

8 个 rank 进程常驻占满 8 卡；预热后每次 prompt 只跑计算。

host cache 是独立 daemon：只有 tp8-fidelity 的 D→P 需要；全量 268.9 GiB，冷页缓存约 3–9 min（热约 3 min）。ep8 勾选只会白等加载。
使用说明（三步 / 参数 / 口径 / 注意事项 / 常见错误）

0) 第一次用？先跑一个冒烟点

  1. 左侧进入「多点 / 批次」，点预设 「冒烟 8k（1 点）」（或卡片顶部「快速上手」里的按钮）。
  2. 复制页面最上方「生成的脚本」里的第一条（无 prof 稳态）命令，粘贴到终端。
  3. 跑完看命令回显的日志目录：<out>/L8192/results.tsv 与 <out>/L8192/logs2/rank0.log。

字段标题悬停有说明与格式；正式采集再选「8 点 / 16 点」矩阵。

1) 三步跑起来

  1. 终端 A：先 npu-smi info 确认 8 张卡空闲（有别的容器进程就先别起）→ 需要 tp8 时手动开 host cache → 执行 bench_server.py start （前台阻塞，Ctrl-C 整组停）。
  2. 终端 B：bench_cli.py warmup（W1/W2/W3，带进度条）→ 队列里的每条 run --prompt ... --chat（prefill → decode）。
  3. 收尾：bench_cli.py status/stop；host cache 是独立 daemon，必须单独 moe_host_cache.py stop。

每次重启 bench_server 都要重新 warmup（AC/池/形状缓存都在进程内）。

2) 参数

modeep8（默认，已验证）= 同布局，P→D/D→P=0，decode 默认增量 （pinned host NZ，~2.2 s/tok）；显式选 full 才是全量重算（0.26 s/tok，数值基线）。 ep8-fidelity = EP 请求级 P→D（device EP NZ，不再每 token 回拷；D→P 从 host cache 回 raw；需 host cache；8 token 验证 **~0.37 s/tok**）； tp8-fidelity = 真实 P→D/D→P + TP 增量 decode （必须 host cache；10 token 验证 0.21–0.32 s/tok）； auto 兼容旧口径（一律 ep8）；tp8-dual 未实现。
serve-l-max常驻池容量：prompt + decode 的总 token 数不能超过它（默认 1024， 不中途重分配）。超长请求会被拒绝。
预热阶梯每个长度第一次出现要现场建 rope/slot/元数据缓存；阶梯覆盖到 ≤L 时 首触也承诺 ≤3 s。默认 16,32,64,128,256,512,1024，单桶约 0.15–0.2 s。
decode / repeat--decode 是上限；命中 EOS 提前结束是正常的。 repeat 从第 2 次起取稳态中位。
--chat用聊天模板（推荐开）。raw prompt 也会自动补长到 ≥16 token。
请求队列预热只在队列开始前做一次；每条请求独立计时、互不影响 （服务端每个请求都会重置状态）。每个请求可以有各自的 chat / thinking / decode / repeat。
host cache只有 tp8-fidelity 需要：269 GiB，冷页缓存约 3–9 min（热约 3 min）； 用完手动 stop。
dry-run给 start/warmup/run 追加 --dry-run，只打印将要执行的 命令、不连接也不占卡；status/stop/host cache 会被注释掉。
多点 --points选「多点 · --points」卡片：编辑点位表（L / hit / batches / replay / replay_tail / 备注）或「上传 / 粘贴 points.json」导入。点位传递方式三选一： 文件（默认，下载 points.json 后把路径填进卡片）、 内联简写（--points-spec，每点 L@hit/bN/r0|1[/tTAIL]）、 内联 JSON（--points-json，紧凑数组）。内联模式不需要文件，points.json 仍可下载留档。 复制两条命令（① 无 prof、② 带 prof，完整脚本里两条都会顺序执行）。 L 必须是 128 的倍数；hit 可写 0.96 或 96（导出统一成小数）； replay_tail 留空 = 用全局 KEEP（140，DeepInfer V4.1）。备注列只留在页面与分享链接里，不会写进 JSON。 MoE 后端用 --moemode 显式传给两条命令（脚本会 unset 同名环境变量，环境变量写法无效）。
导入 / 导出“导入 / 导出”可下载 JSON、上传 JSON 或复制带 #cfg= 的分享链接；打开页面时自动恢复。

3) 指标口径

  • prefill：8 rank 取 max，不含 tokenize；实测 ep8 稳态 ~0.16 s、首触 ~0.34 s。
  • decode：每 token 单独计时。默认都走增量：ep8 增量 （pinned host NZ）2.16–2.30 s/tok；ep8-fidelity（P→D device NZ） **0.37 s/tok**（8 token 已验证）；ep8 full（数值基线）~0.26 s/tok； tp8 增量 TP 0.21–0.32 s/tok（10 token 已验证）。首 token 不计入。
  • P→D / D→P：ep8 都是 0；tp8 P→D 2.5–3.2 s、D→P 4.9–5.5 s， D→P 后下一 prompt prefill 1.8–2.2 s。
  • 承诺：L ≤ 预热阶梯最大值（且 prompt+decode ≤ l_max）时 prefill ≤3 s； 超出显示实测、不承诺。
  • 多 prompt：队列里每条都单独打印 prefill / P→D / decode / D→P / 文本； 看稳态时用 repeat ≥ 3 取中位。

4) 注意事项

  • 共享卡：起服务前 npu-smi info 要是 8 张卡都没有别的进程。 被别的容器占着会出现 halSqCqAllocate / RunAicpuCommInit 这类驱动错误：停服务、等 20–30 s、确认空闲再重启；不要 kill 别人的进程。
  • 根盘紧张：勾选“临时目录放共享盘”，并在终端 B 也 export 同一个 DS41_BENCH_ROOT。
  • prompt 补长：chat 在 BOS 后插空格；raw 在末尾补；增量 decode 补到奇数 （≥16，ratio=2 部分组边界）；full decode 用偶数长度（单次 prefill，避开 T%4==1 trap）。
  • 文本显示：结果表格的“文本”列只放 40 字预览，完整文本在下面单独打印； 命中 EOS 可能只是正常句末。
  • 日志：<logdir>/rank*.log + all.log； 每次 run 结果里也会打印 tail -f 命令。
  • tp8 增量已验证（2026-10-20）：10 token 文本连贯、0 崩；此前乱码的两个根因 （inc 未写回环境误跑 full；`hit_replay_tail` 在每步抑制压缩 KV 写入）都已修。 奇数绝对位置的 carry 仍是近似（会打提示），尚未与 full 逐位对拍。

5) 常见错误

prompt + decode > 池容量加大 --serve-l-max 重启； 池不中途重分配。
tp8 需要 host cache先 moe_host_cache.py start，或改用 ep8。
halSqCqAllocate / aicore exception共享卡被占或驱动状态差：停服务、等 20–30 s、npu-smi 确认空闲后重启；反复出现找管理方清容器/驱动。
RunAicpuCommInit … get kernel failedHCCL 通信域 lazy init 失败； 新版启动会先预热 WORLD 域。仍失败按上一条处理。
文本停在半句先看完整文本/ids：命中 EOS 是正常结束；表格里只是 40 字预览。
控制连接断开 / rank 超时有 rank 异常退出，看门狗整组杀（HCCL 不能单 rank 重启）；重启服务并重新 warmup。
